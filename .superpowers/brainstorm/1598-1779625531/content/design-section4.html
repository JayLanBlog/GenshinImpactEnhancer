实现策略

📊 预设性能数据（离线硬编码 + 在线更新）

每个预设附带一个 JSON 描述文件，记录在多个基准硬件上的性能表现。首次安装时打包在应用里，后续通过 GitHub Release API 拉取更新。 

{
  "cinematic": {
    "rtx4060_1080p": {"gpu_util": 68, "est_fps": 144},
    "rtx4060_1440p": {"gpu_util": 82, "est_fps": 100},
    "gtx1660_1080p": {"gpu_util": 95, "est_fps": 58},
    ...
  }
}

🌐 社区偏好数据（匿名上报）

用户选择预设后，匿名上报（需要用户同意）：GPU型号 + 分辨率 + 选择的预设。服务端做简单聚合统计，返回"同配置玩家偏好分布"。 

// 客户端请求
POST /api/stats/hardware-preset
{ "gpu": "rtx4060", "resolution": "1440p" }

// 服务端响应
{ "cinematic": 62, "bright": 23, "realistic": 15 }

💡 为什么不用真正的 ML 模型？

不需要。着色器预设的性能表现是可精确测量的确定性问题，不是需要通过训练来拟合的概率问题。一个加权评分算法（基准数据 70% + 社区偏好 30%）已经足够精准。引入 ML（如 ONNX Runtime）只会增加包体积（~50MB+）和运行时开销，收益几乎为零。

这节AI 推荐引擎设计——加权评分 + 离线数据 + 社区统计，有没有不同意见？
