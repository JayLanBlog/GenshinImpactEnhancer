📋 设计确认 · 第5节：错误处理 & 容灾策略

这是一个游戏注入工具——容错能力直接决定用户体验和口碑

💀 五大关键故障场景 & 应对

❌ 1. 注入失败 游戏更新偏移变了 / 杀毒拦截 / 权限不足
应对：降级启动——ReShade 注入失败 → 只启动游戏（纯净模式），弹出明确提示。
FPS Unlock 失败 → ReShade 仍可工作。每个引擎独立判断，部分失败不影响其他。
💥 2. 游戏中途崩溃 Hook 冲突 / 驱动问题 / 模组不兼容
应对：崩溃信息自动捕获 → 生成诊断报告 → 下次启动时提示"检测到上次崩溃，是否以安全模式启动？"
安全模式 = 仅注入最基础的 DX Hook，不加载任何自定义着色器/Mod。
📉 3. 性能异常（着色器开销突然飙升） 某个着色器写坏了 / 新版本不兼容
应对：性能仪表盘实时监控 → 如果 FPS 低于基准值 50% 超过 5 秒 → 游戏内 Overlay 弹出警告，"检测到性能异常，按 Ctrl+Shift+R 禁用最近启用的着色器"
🔄 4. 游戏版本更新 → Hook 失效 原神更新后内存布局变化
应对：每次启动时对比游戏 .exe 的版本哈希 → 如果版本变更，自动从 GitHub API 下载最新偏移表。
如果 API 也没有 → 回退到本地已知最后有效版本，尝试"前向兼容模式"（通过特征码搜索偏移）。
🌐 5. 网络不可用 → AI 推荐 / 更新 / 社区数据失效 断网 / API 挂掉
应对：全离线可用。AI 推荐退化为纯本地评分（只用性能数据），社区偏好权重置零。
静默降级，不弹错误框干扰用户。
