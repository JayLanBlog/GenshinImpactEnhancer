🔑 核心测试手段

🧪 Test.Genshin 集成测试项目

创建一个 Mini DX 目标进程（极简 DirectX 程序），
用它来模拟真实游戏环境，无需启动原神。

✅ 编译速度：< 3 秒
✅ 启动速度：< 1 秒
✅ 本地/CI 均可运行

📏 偏移验证自动化

每次 CI 运行：
1. 拉取最新偏移表 JSON
2. 校验所有偏移范围合法（不对空地址/野指针）
3. Schema 校验 → 防止结构破坏
4. 如果有测试用 Mini DX 程序 → 验证偏移可解析

🤖 CI 流水线（GitHub Actions）

git push →
├── dotnet build
├── dotnet test (单元 + 集成)
├── 偏移表 Schema 校验
└── 生成 Release 包

⚠️ 不测试什么（实事求是）

❌ 不在 CI 中测试「真实游戏注入」 — 需要完整游戏客户端，不可行。
❌ 不测试「特定 GPU 上的画质表现」 — 没有 GPU 矩阵 CI。
❌ 不强求 100% 覆盖率 — Native 代码的高覆盖率不切实际。

✅ 真实注入测试 — 靠 Release 发布前的 人工冒烟测试 + 社区 Beta 频道反馈。

测试策略合理吗？重点测能自动化的，承认不能自动化的。
